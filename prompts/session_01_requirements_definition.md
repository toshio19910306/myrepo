# セッション01: 要件定義フェーズ

## ユーザーからの要求
- データを加工するようなバッチを作成してください
- CSVからSQL Serverへ変換したい
- 実行頻度は１日１回
- データ量は１ファイル１万件
- CSVの項目は月々の人工の作業実績（工数や費用、作業内容、発注金額等）
- そのままの項目でSQL Serverに格納したい
- 今まだ決まっていないので、独自で決めてもらっていい

## システムからの提案
- 人工作業実績データのCSVからSQL Serverへの変換バッチシステム
- 日次実行（1日1回）
- 1ファイル1万件の処理
- フロントエンド（Next.js 15 + TypeScript + bun）とバックエンド（Rust/Go）の分離アーキテクチャ
- Azure環境での運用

## 作成した要件定義書
1. **業務要件定義書** (`business_requirements.md`)
   - データ収集業務、データ変換業務、データ管理業務の定義
   - 業務フロー図（Mermaid形式）
   - ステークホルダーと制約事項

2. **機能要件定義書** (`functional_requirements.md`)
   - 9つの主要機能（ファイル処理、DB操作、エラーハンドリング、監視・管理、設定管理）
   - ユースケース図
   - 画面・インターフェース要件

3. **非機能要件定義書** (`non_functional_requirements.md`)
   - 可用性要件（99.5%稼働率）
   - 性能要件（1万件10分以内処理）
   - セキュリティ要件（Azure AD認証、暗号化）
   - Azure環境要件

4. **CSVスキーマ定義書** (`csv_schema_definition.md`)
   - 11項目のCSVフィールド定義
   - バリデーションルール
   - サンプルデータとエラーパターン

5. **SQL Serverスキーマ定義書** (`sql_server_schema_definition.md`)
   - 4つのテーブル設計（作業実績、社員マスタ、プロジェクトマスタ、バッチ履歴）
   - インデックス、外部キー、トリガー定義
   - ビューと初期データ

## 技術スタック
- **フロントエンド**: Next.js 15 App Router + TypeScript + bun
- **バックエンド**: Rust または Go
- **データベース**: Azure SQL Database (SQL Server)
- **インフラ**: Azure (Japan West)
- **テスト**: bun test (フロントエンド), Playwright (E2E)
- **デザイン**: TailwindCSS + デジタル庁デザインシステム
